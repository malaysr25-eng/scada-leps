## 2. Changed: `backend/services/twin.py`

The twin's conveyor comparison still used the old run-coil gate: *"Run output
is ON but encoder feedback reads zero."* On the real cell that is the same
false positive as `FINDINGS_2026-09-21.md` §4. It is a WARNING, not a
FAULT, so it never broke a cycle, but it would log a "DIGITAL TWIN MISMATCH"
through every 63.8 s park.

Now it uses the same gate as `Diagnostics._run_without_motion`:
- the axis must be away from `Set_Position` by more than `position_tolerance`
  (0.5);
- then a `motion_grace_s` (2.0) ramp-up grace applies.

This applies to both the MISMATCH branch and the DIVERGENT branch. Without
the gate on DIVERGENT, a parked axis (0.15 commanded, 0 feedback) would have
tripped it instead. Both defaults are in code, so `digital_twin` in
`config.json` needs no new keys.

Verified in the simulator:
- a clean cycle logs **0** conveyor twin mismatches (it was 3: one per belt,
  on the first poll after `Set_Position` changed);
- the injected stall still gets flagged, on conveyor 2 only.
