## 3. Why the motion-fault fix looks the way it does

`Conveyor1..3` are **station enables, not motor-running signals**. From the
2026-09-21 capture (`cycle_A_engraved_1559_timeline.txt`, cycle `C0004-155943`):

```
t=20.653  conveyor2 coil 0 -> 1
t=22.189  set_position 30.0 -> 2.0   axis moves, vel -47.562
t=22.936  position_fb = 2.0          vel 0.0  <-- correct, axis at target
          ... 63.8 s parked, coil still ON ...
t=86.753  set_position 2.0 -> 30.0   axis moves back
t=87.505  position_fb = 30.0         vel 0.0, coil 1 -> 0
```

The old check faulted ~2 s into that 63.8 s park, on every cycle, which drove
`AUTO_RUNNING -> FAULT -> RECOVERY_REQUIRED`, so no cycle ever closed as
COMPLETED, nothing was written to `cycle_history`, and the timings extractor
saw nothing. That is `FINDINGS_2026-09-21.md` §4.

`Goto_Position` was deliberately **not** used as the gate: it does not appear
anywhere in the 2026-09-21 captures, so nothing establishes its behaviour.

pre-existing timing sensitivity, not a regression.
